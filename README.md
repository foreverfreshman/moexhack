# MOEX ArenaGo — автономный торговый агент

Автономный торговый бот для контура ArenaGo (MOEX AI Hackathon). Управляет
портфелем из 20 ликвидных акций MOEX, принимает решения о покупке/продаже/удержании
на основе количественных сигналов и LLM-фильтрации новостного риска. Работает
полностью без ручного управления, восстанавливается после сбоев.

## Ключевые решения (для быстрого ознакомления)

Три идеи, на которых построено решение:

1. **Отказ от ML в пользу робастного momentum.** На этапе исследования ML-подходы
   (LightGBM, LambdaRank, meta-labeling) показали результат хуже наивного momentum
   на out-of-sample данных — переобучение на зашумлённых рядах. Ставка сделана на
   простой проверяемый сигнал, а не на сложную модель, разваливающуюся на тесте.
2. **LLM как риск-фильтр, а не предсказатель цен.** LLM не генерирует сделки
   (ненадёжна в численном прогнозе) — она направленно блокирует gap-фейд, только
   если свежая новость фундаментально оправдывает движение. Узкий критерий,
   fail-open при любой ошибке.
3. **Отказоустойчивость как требование, а не опция.** Recovery со сверкой биржи,
   reconcile при таймаутах, идемпотентный счётчик дней, kill-switch — бот рассчитан
   на полностью автономную работу с восстановлением после перезапусков.

## Краткое описание подхода

Бот сочетает две проверенные на исторических данных стратегии и LLM-надстройку
для управления риском:

1. **Cross-sectional momentum (mom_21)** — основной источник альфы. Ранжирует
   20 акций по 21-дневной доходности, лонгует топ-3, шортит дно-3. Ребалансировка
   раз в 2 торговых дня.
2. **Gap Fade** — внутридневная mean-reversion. Фейдит утренние гэпы (ставит на
   возврат цены к предыдущему закрытию), закрывает позиции внутри дня по
   take-profit / stop-loss или принудительно перед вечерним аукционом.
3. **LLM news filter** — риск-надстройка на открытой модели (Qwen, Apache 2.0)
   через polza.ai с веб-поиском. Накладывает вето на gap-фейд, если свежая
   новость фундаментально оправдывает движение (тогда возврат маловероятен).

Распределение капитала: 55% momentum / 45% gap fade. Доли подобраны бэктестом
на 14-дневных скользящих окнах (см. «Обоснование решений»).

## Архитектура

```
main.py              — оркестратор: фазовый автомат дня, исполнение, риск, recovery
├── strategies/
│   ├── mom21.py      — cross-sectional momentum
│   └── gap_fade.py   — gap fade с side-aware TP/SL и news-вето
├── data/
│   └── tinvest_stream.py — рыночные данные через T-Invest API (цены, лоты, свечи)
├── arenago_client.py — REST-клиент ArenaGo (ордера в лотах, позиции, типизированные ошибки)
├── portfolio.py      — расчёт целевых весов → позиции → ордера (diff)
├── monitor.py        — SQLite-персистенс (состояние, сделки, PnL) + риск-монитор
├── news_filter.py    — LLM-фильтр новостного риска (polza.ai)
├── Dockerfile        — единый контейнер (требование платформы)
└── requirements.txt
```

Фазовый автомат торгового дня (время МСК): `prepare` (09:55, загрузка данных) →
`open` (10:00, ребаланс momentum + открытие gap-фейдов) → `monitor` (мониторинг
TP/SL раз в 30 сек) → `eod` (18:48, закрытие gap-позиций до вечернего аукциона).
Momentum-позиции удерживаются overnight, gap-позиции — только внутри дня.

## Обоснование решений

**Почему momentum + gap fade, а не ML?** На этапе исследования тестировались
ML-подходы (LightGBM, LambdaRank, meta-labeling) для предсказания доходности.
На реальных данных они показали результат **хуже наивного momentum** — классическая
проблема переобучения на зашумлённых финансовых рядах с низким отношением
сигнал/шум. Простой cross-sectional momentum дал стабильно положительный Sharpe
на out-of-sample окнах. Поэтому ставка сделана на робастный количественный сигнал,
а не на сложную модель, которая хорошо выглядит на трейне и разваливается на тесте.

**Почему ребаланс раз в 2 дня?** Бэктест 1-дневной, 2-дневной и 3-дневной ребалансировки
показал, что 2-дневная даёт сопоставимую доходность при меньшем обороте и
комиссиях (выше Sharpe).

**Почему доля 55/45?** Поиск по сетке распределений капитала (от 5/95 до 95/5,
шаг 5%) на 14-дневных окнах: доходность монотонно растёт с долей momentum, оборот
падает. Доля 55/45 — баланс между доходностью и гарантией прохождения порога
оборота 10M ₽ (P10 оборот ≈ 10.8M, вероятность ≥10M ≈ 95%).

**Об обороте.** Весь торговый оборот бота органический — он формируется реальными
торговыми решениями двух стратегий: ребалансировкой momentum (раз в 2 дня) и
ежедневными gap-фейдами (вход на открытии, выход по TP/SL или EOD). В коде нет
транзакций, совершаемых исключительно ради увеличения оборота (wash-trades);
каждая сделка — следствие сигнала стратегии. Объём ≥10M достигается естественно
за счёт 14 торговых дней автономного периода.

**Почему Gap Fade закрывается внутри дня?** Гэп — это разрыв на ночном/недельном
перерыве, перереакция на котором статистически возвращается к норме в течение дня.
Удержание overnight добавило бы риск нового гэпа без улучшения edge.

## Роль LLM 

LLM не предсказывает цены и не генерирует сделки — это сознательное решение
(LLM ненадёжны в численном прогнозе). Её роль — **направленный риск-фильтр**:
перед открытием gap-фейда модель проверяет свежие новости по тикеру и блокирует
сделку, только если новость фундаментально оправдывает движение гэпа (например,
гэп вниз на фоне реальных санкций — тогда это не перереакция, а обоснованная
переоценка, и фейд опасен). Критерий узкий: блокировка — редкое исключение,
по умолчанию сделка разрешается. Фильтр автоматически отключается, если оборот
отстаёт от целевого темпа или в последний торговый день (приоритет — оборот).

Используется открытая модель Qwen (лицензия Apache 2.0, свободное коммерческое
использование) через агрегатор polza.ai с веб-поиском по надёжным источникам
(Интерфакс, e-disclosure, MOEX, РБК, ТАСС). При любой ошибке/таймауте LLM фильтр
не блокирует сделку (fail-open) — LLM не является точкой отказа.

## Управление рисками и отказоустойчивость

Бот спроектирован для полностью автономной работы на этапе 2, включая обработку
внутренних ошибок и восстановление после сбоев:

- **Recovery при старте** — состояние восстанавливается из SQLite (`/data`), затем
  сверяется с фактическими позициями биржи (биржа — источник истины). Предотвращает
  наслоение позиций при перезапуске.
- **Reconcile при таймаутах** — если ответ на ордер не получен, бот сверяется с
  биржей и приводит учёт к факту, устраняя рассинхрон.
- **Capital-aware исполнение** — при нехватке средств ордер усекается до доступного
  объёма вместо отклонения.
- **Корректная работа с лотами** — количество конвертируется штуки→лоты на границе
  с ArenaGo (учёт реальных размеров лотов из T-Invest API).
- **Kill-switch** — при дневной просадке −5% позиции принудительно закрываются
  (защита от каскадных потерь при сбое данных или аномалии рынка).
- **Retry с backoff** — сетевые операции переживают временные сбои инфраструктуры.
- **Идемпотентный счётчик дней** — перезапуск в тот же торговый день не сбивает
  ребаланс-расписание.

Всё персистентное состояние (`bot_state.db`, логи) хранится в `/data` — переживает
редеплои и перезапуски.

## Развёртывание

Единый Docker-контейнер (требование платформы). Сборка из `Dockerfile` в корне.

**Переменные окружения:**
- `SANDBOX_API_KEY` — ключ ArenaGo (прокидывается платформой автоматически,
  на этапе 2 заменяется на боевой). Бот читает только из env.
- `POLZA_API_KEY` — ключ polza.ai для LLM-фильтра (устанавливается через модератора). 
  Захардкожен, без него бот работает без новостного фильтра.
- `BOT_DATA_DIR` — каталог состояния (по умолчанию `/data`).

Без подключённого диска `/data` бот делает fallback на рабочий каталог.

## Для экспертов: как разобраться и проверить

**В продакшене запуск автоматический** — платформа собирает образ из `Dockerfile`
и запускает `CMD ["python", "main.py"]`. Никаких ручных команд запуска не требуется;
бот сам определяет фазу торгового дня и начинает работать. Ниже — как воспроизвести
и проверить решение локально.

Сборка и запуск контейнера локально (как в проде):
```bash
docker build -t arenago-bot .
docker run --rm -e SANDBOX_API_KEY=<ключ_arenago> arenago-bot
```

Прогон тестов без контейнера:
```bash
python main.py --mock        # смоук полного цикла: открытие/мониторинг/EOD/kill-switch
python test_10days.py        # симуляция 14 торговых дней
python news_filter.py        # проверка LLM-фильтра на живых новостях (polza.ai)
python strategies/gap_fade.py # юнит-тесты gap fade
```

Где что искать в коде:
- **Логика принятия решений** — `main.py`, метод `_do_open` (ребаланс + gap-входы)
  и `_monitor_tick` (выходы по TP/SL, kill-switch).
- **Сигналы стратегий** — `strategies/mom21.py` (momentum) и `strategies/gap_fade.py`
  (gap fade с направленным news-вето).
- **LLM-фильтр** — `news_filter.py` (промпт, направленная логика, fail-open).
- **Отказоустойчивость** — `main.py`: `_sync_with_broker` (recovery),
  `_reconcile_ticker` (таймауты), `_init_new_day` (идемпотентный счётчик дней).

Что бот пишет в логи (для диагностики через мониторинг):
- старт: баннер, `Resolved 20/20 FIGIs`, `News filter активирован`;
- открытие: `Gap entry`, `NEWS_CHECK ... verdict=OK/VETO`, `[mom]`/`[gap]` ордера;
- закрытие: `gap-exit:take_profit` / `gap-exit:stop_loss` / `gap-eod`;
- ежедневно: `RISK SUMMARY` (PnL, оборот);
- heartbeat раз в 10 минут (подтверждение, что бот жив).
